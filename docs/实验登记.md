# 实验登记表

本表登记检测阶段已经跑过的全部实验，记录每个实验的来源配置或脚本、重跑命令和关键参数。建立本表的目的，是在清理 output 产物之后，仍然保留"哪些实验存在过、如何重新生成"的完整记录。所有结果都可以按本表重跑，因此原始产物可以删除，需要时再生成。

本表对应一次 output 目录的清理与结构重整。

## 背景说明

实验都在实验服务器上运行，结果通过 `scripts/sync_lab.ps1 pull` 拉回本地。可复用的缓存保存在 `output/cache/profiles/`，包含三个检测模型的标定统计和分类模型的 profile，这部分清理时保留，不需要重新计算。

服务器侧启动器是 `scripts/lab_run_det.sh`，它自动挑选显存占用最低的 GPU 运行 `run_fuzz.py`，遇到抢不到卡或 OOM 时等待重试。配置类实验都通过它启动：

```bash
nohup bash scripts/lab_run_det.sh configs/det/<名字>.toml > output/det/<名字>_run.log 2>&1 &
```

## 反馈循环与消融实验

这一组每个实验对应 `configs/det/` 下的一个配置，输出目录写在配置的 `[run] out` 字段。重跑命令统一是 `uv run python scripts/run_fuzz.py --config configs/det/<名字>.toml`，或通过上面的服务器启动器。

| 输出目录 | 配置 | 说明 |
|----------|------|------|
| output/det/base | base.toml | 完整全流程：50 轮反馈循环 + 基线差分 + 结构归因 + 真值核验 + 层级消融 + 自然与生成失效对比。200 张图。 |
| output/det/struct | struct.toml | 只跑分析（max_iterations=0）：基线差分 + 归因 + 真值核验 + 层级消融。对应实验矩阵 E1/E2/E4。 |
| output/det/nofb | nofb.toml | 关闭动态反馈的消融，使用静态权重。 |
| output/det/diff | diff.toml | 差分相关的消融变体。 |
| output/det/random | random.toml | 随机基线对照。 |
| output/det/corrupt | corrupt.toml | 用 COCO-C 风格腐蚀替代 PGD 作为诱发手段，腐蚀强度 severity=3。对应 E7。 |
| output/det/yolo4 | yolo4.toml | 加入 YOLO 作为黑盒投票者的实验。 |
| output/det/yolo_target | yolo_target.toml | 以 YOLO 相关设置为目标的实验。 |

## 腐蚀强度扫描

`corrupt_s1 / corrupt_s2 / corrupt_s4 / corrupt_s5` 没有独立配置，它们是在 `corrupt.toml` 基础上把 `[optimize] corruption_severity` 改成 1、2、4、5 得到的，用于扫描腐蚀强度对四类失效的影响（severity=3 即上面的 corrupt）。

重跑方式是以 corrupt.toml 为基础覆盖 `corruption_severity`。可以为每一档建立一个 extends corrupt.toml 的小配置（只改 `[run] out` 和 `corruption_severity`），再用标准入口运行；输出目录对应写成 `output/det/corrupt_s<档位>`。

## 扩规模实验

`scale_*` 是对应基础实验的扩规模版本，设置相同但样本更大：迭代轮次 50→120，每轮种子数 4→8，差分与归因图数 200→400，生成侧签名样本 50→100。目的是为正式数字和结构签名的稳定性提供更大样本，并与 50 轮版本对照。参数定义在 scale.toml，其余 scale 配置 extends 它。

## 修复试点（E8）

修复试点用 `scripts/run_repair_pilot.py` 运行，对某类失效做不依赖训练的通道缩放，验证结构归因的因果性。固定设置：A、B 集各取 COCO val2017 的 300 张图、互不相交，责任层取 256 通道里归因最高的 64 个。详细方法和结果记录在 `docs/paper_plan/Day6/E8修复验证试点.md`。脚本默认参数对应定位偏移那一组（`--kind loc --target fcos --layer head.regression_head.conv.0 --out output/det/repair_pilot`），其余组通过修改 `--kind / --target / --layer / --out` 得到。

| 输出目录 | 失效类别 | 目标模型 | 责任层 | 缩放方向 |
|----------|----------|----------|--------|----------|
| output/det/repair_pilot | 定位偏移 loc | FCOS | head.regression_head.conv.0 | 抑制（强度<1） |
| output/det/repair_pilot_spurious | 虚检 spurious | Faster R-CNN | backbone.fpn.inner_blocks.0.0 | 抑制 |
| output/det/repair_miss | 漏检 miss | RetinaNet | backbone.fpn.inner_blocks.0.0 | 放大（强度>1） |
| output/det/repair_miss_supp | 漏检 miss | RetinaNet | backbone.fpn.inner_blocks.0.0 | 抑制 |
| output/det/repair_cls | 误分类 cls | FCOS | backbone.fpn.inner_blocks.0.0 | 抑制 |
| output/det/repair_grad | 定位偏移 loc | FCOS | head.regression_head.conv.0 | 沿 IoU 梯度的单步方向编辑（`run_repair_grad.py`） |

重跑命令的形式（以虚检为例，其余组替换对应参数）：

```bash
uv run python scripts/run_repair_pilot.py \
  --kind spurious --target faster_rcnn \
  --layer backbone.fpn.inner_blocks.0.0 \
  --num-a 300 --num-b 300 --topk 64 \
  --out output/det/repair_pilot_spurious
```

漏检的放大组与抑制组靠 `--strengths` 区分：放大用大于 1 的强度档，抑制用小于 1 的强度档。各组的确切强度档以 E8 文档为准。
