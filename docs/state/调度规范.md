# 调度规范

调度者管一组工作流。它把任务派给 worker，检查 worker 的成果，决定提交和合并。提交和合并的权限只在调度者，因为它有全局视野，一次只处理一条流，能避免多个成果同时提交又同时合并。

## 角色分工

| 角色 | 做什么 | 不做什么 |
|------|--------|----------|
| worker | 在指定工作区里产出成果，完成时写自己的工作流文件，把结果返回调度者 | 不提交，不合并 |
| 调度者 | 派发、检查、提交、合并，写自己的调度文件 | 不亲自做 worker 的活 |

## 写状态的时机

调度者在每次做决定时写自己的调度文件：派发、检查、提交、合并、判断要等。不放在会话结束时，因为会话何时结束不可知。

## 每日开工与收工

工作分三层。docs/paper_plan/路线图.md 是总故事和顺序；每条流的「作业队列」是它长期的待办；调度文件的「今日计划」是今天从各流队列挑出来推的事，只指向队列项，不重抄。

开工：

1. 读 BOARD、自己管的流文件、自己的调度文件，弄清现在到哪了。
2. 对着路线图当前阶段和各流队列，和用户核对今天推什么，写进「今日计划」。
3. 按计划把作业派给 worker，进各自工作区。

收工：

1. 当天 worker 的成果检查、提交、合并，向用户汇报提交了哪些内容。
2. 更新各流文件：确认的结论追加进「已知上下文」并标已复核，更新作业队列的下一步。
3. 在调度文件里留下当天的检查合并记录和明天的起点。

## 派一个 worker

1. 选一条流，读它的 `owner`。被占就换一条。
2. 认领：把 `owner` 改成这个 worker，`status` 改成 `in-progress`。状态文件在主检出里改。
3. 写任务说明，指向这几样：这条流的工作区路径、它的工作流文件、具体任务、相关代码和文档、完成标准、成果写到工作区哪里、状态写回主检出哪条流文件。
4. 实验作业先看 BOARD 的 GPU 队列，先来后到排队，再派。

> worker 能读到启动者主检出的 CLAUDE.md 和 memory，规范不必重讲。前提是不用框架自带的 worktree 隔离，工作区由我们自己用 jj 管。

## 检查、提交、合并

worker 返回的结果只有调度者看得到，先把要紧的转告用户，然后：

1. 按完成标准检查成果，不合格就让它返工。
2. 当 worker 的第二个证人，复核它对「已知上下文」的改动：独立核新升的结论和删掉的条目，核当下的产物、必要时重跑，不是信叙述。会被后面当地基的结论，加派一个冷启动审查 worker 独立复核。复核在流的「记录」里留一行带日期的痕迹。
3. 合格就在这条流的工作区里提交，封存成果。
4. 把成果并进主线，按下面「分支同步与合并」一节做。
5. 向用户汇报提交了哪些内容，结论的升级和删除要点出来。
6. 这条流还要继续就再派 worker，做完把 `status` 改成 `done`。

> 提交和合并只由调度者做，一次一条流，所以不会有多个成果同时提交又合并。
> 调度者自主提交，不必逐次问用户；但每次提交后必须向用户汇报提交了哪些内容。这是本工作流对"只在用户明确要求时才提交"的一处放开，只限调度者在工作区里封存和合并流成果，不是随意提交。

## 分支同步与合并

主线是 `linux` bookmark。所有工作区，包括主检出，地位平等：各自从当前 `linux` 头长出来，在自己这条线上线性提交。

每次同步两步，对每条分支做法一致：

1. 确定新的 `linux` 头。挑一条分支的最新提交作为新头，在那条分支的工作区里把 `linux` bookmark 移到它上面。这条分支就完成了，不再做别的。
2. 其余每条分支把自己的工作 rebase 到这个新头上，各自在自己的工作区目录里做。各流改的路径不相交，所以 rebase 是干净的。

一条没有新改动的分支，第二步会退化：它没有要 rebase 的东西，只需在新头上 `jj new` 一个空提交接着用。这对任何空闲的分支都成立；主检出只是最常处于这种状态的那一个，所以平时拿它举例。

冲突只在两条分支动了同一个文件时才出现。那时 jj 给一个带标记的冲突，去解开它。

## 多个调度者怎么共处

调度者可以有好几个。靠三条规则不打架。

1. 每个信息只放一个地方。流谁在做，看流的 `owner`；GPU 上跑什么，看 BOARD 队列；调度者自己的进度，看它自己的调度文件。不写两份。
2. 调度者之间不直接通信，靠读共用文件错开。派 worker 前先看流的 `owner`，被占就避开。
3. GPU 一次只跑一个，谁要跑实验都按 BOARD 队列先来后到排，跑完让出来。

最上面是用户本人。用户开几个调度者会话，给每个分一组流来管，在 BOARD 的调度者登记里记一行。调度者之间不需要再加一层 meta 调度者。
