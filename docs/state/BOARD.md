# BOARD

多会话状态的总入口。仓库是唯一的真实记录，会话是临时的，状态留在文件里。本文件给出当前进度、工作区布局和工作流的记录规范。调度者的规范见 调度规范.md。

## 写状态的时机

只在能观测到的动作上写状态，不依赖会话结束，因为会话何时结束不可知。

- worker：在自己完成时，写它负责的工作流文件。
- 调度者：在每次做决定时（派发、检查、合并），写自己的调度文件。

## 工作区

每条流有自己的、长期存在的 jj 工作区，反复复用，集中放在主检出之外的一个父目录下。工作区自包含：这条流的成果写在里面，被忽略的共享数据通过符号链接接进来。

| 流 | 工作区 |
|----|--------|
| 实验 | `F:/doc/安全缺陷/工作区/实验` |
| 写作 | `F:/doc/安全缺陷/工作区/写作` |
| 可视化 | `F:/doc/安全缺陷/工作区/可视化` |
| 审计 | `F:/doc/安全缺陷/工作区/审计` |

约定：

- 新建工作区后跑一次引导，把被忽略的共享目录符号链接进去：`output_det`、`references`、`datasets`、`.venv`，都指向主检出。这四个名字已写进 `.gitignore`，所以 jj 不跟踪这些链接。
- 凡是和某个工作区有关的 jj 操作（快照、提交、rebase），都在那个工作区的目录里执行，不在主检出里执行。
- 状态文件（docs/state/）的写只在主检出，保持单一真相源。工作区里也有一份 docs/state，那是提交基线、供读取，靠 rebase 从主检出刷新；不在工作区里改它，免得几个工作区各改 BOARD 造成分叉。
- 实验要把源码同步到服务器时，从主检出跑 `sync_lab.ps1`（脚本按自己所在位置定仓库根），调度者把流的代码合并到主之后再同步，服务器拿到的是整合版本。
- 不必把 `AGENTS.md` 放进工作区。worker 读的是启动者主检出的那份。
- 成果的提交与合并只由调度者做，见 调度规范.md。worker 不提交。

## 工作流文件格式

位置：`streams/<名字>.md`，一条工作流一个文件。内容自足，新会话只读这一个文件和它指向的产物即可接手。

头部字段：

| 字段 | 含义 | 取值 |
|------|------|------|
| `stream` | 工作流名字 | 与文件名一致 |
| `owner` | 当前负责人 | 负责人标签；空闲写 `none` |
| `status` | 进度 | `idle` / `in-progress` / `blocked` / `done` |
| `updated` | 最后改动时间 | 日期 |

正文小节，按顺序：目标、已知上下文、作业队列与下一步、阻塞、记录、指针。「记录」只往后追加，一条一行，写明做了什么、结果、指向的产物。已知上下文的写法见下一节。

## 已知上下文

每条流的「已知上下文」装"当前为真、且代码里读不到"的知识，是 worker 干活要靠的工作集。它和「记录」分工：「记录」只追加、永不删，是历史；「已知上下文」可随时增删，是当前认识。历史留在「记录」里，所以删这里的条目是安全的。

条目写成一行、自包含，带一个类型标签：

| 标签 | 装什么 |
|------|--------|
| 决定 | 做过的选择和理由 |
| 方法 | 要遵守才能和以前一致的协议 |
| 设定 | 关键参数值 |
| 结论 | 已验证为真的发现，带「已复核」标记 |
| 假设 | 暂定、待验证的判断 |
| 坑 | 操作陷阱 |

生命周期：

- 加：学到一条"为真且代码里读不到"的东西就加。
- 升级：假设被验证就升成结论，见下面的复核。
- 删：被推翻、被取代、底层代码变了、或者已毕业，就删，并在「记录」里记一句删了什么、为什么。
- 毕业：一条结论稳固到该进正式文档或代码时，搬过去，这里只留指针。已知上下文是中转站，不是档案馆。

只装这条流专有的。跨流的项目级决定放路线图或 memory，需要时指过去，不在各流重抄。

升成结论要两个证人：

- 产出它的 worker 是第一个证人，独立复核的审查者是第二个。没过第二个证人的，一直是假设。
- 审查者要独立地核当下的产物、必要时重跑，不是读叙述点头。worker 和审查者是不同的 agent。
- 默认审查者是调度者。会被后面当地基的结论，加派一个冷启动的审查 worker 复核，并写进提交汇报给用户。结论的删除同理。
- 复核在「记录」里留一行带日期的痕迹。已知上下文里结论只标「已复核」，不挂证据。

## 接手与完成

接手：

1. 读目标流的 `owner`。不是 `none` 就表示有人在做，换一条。
2. 把 `owner` 改成自己，`status` 改成 `in-progress`。

完成：

3. 把进展追加到「记录」，更新「已知上下文」、`status` 和 `updated`。
4. 把 `owner` 改回 `none`，结果返回给调度者。

> `owner` 是约定标记，不是锁。它防的是两个会话同时认领同一条流。认领前先读它，被占就换一条。没有工具强制，靠自觉。
