## 目标

归因分析需要覆盖检测任务中的四类失效：虚检、漏检、误分类和定位偏移。每一类失效都需要给出责任层级特征、因果验证结论、可用修复办法和修复代价。虚检和漏检已经完成；这条工作流负责补齐误分类和定位偏移。

## 已知上下文

- [决定] 方法不再限定为 training-free，以产生有效结果为准。
- [方法] A、B 两个数据集不相交。A 用于选择责任通道，B 用于评测。判据使用项目的 differential judge，不使用 mAP。
- [结论] 虚检和漏检可以通过抑制责任通道修复，效果明显超过随机对照，因果性成立。已复核。
- [结论] 定位偏移的因果性成立，但抑制和单步权重调整都没有产生有效修复。已复核。
- [假设] 误分类归因到回归头时，责任通道与随机对照难以区分。可能是归因层选错（应换到分类子网），也可能是归因目标用了概率（见下条决定）。
- [决定] 重跑误分类归因时，归因层换到分类子网，同时把归因目标从 scores_g（概率）改成 NMS 前的 logit。依据审计流的 scores_g 结论：概率在高置信时梯度饱和、压低 grad×act，可能正是责任通道与随机难分的原因。
- [坑] 代码里没有 COCOeval，不要把 mAP 作为判据。
- [坑] profile 缓存的 key 不包含图片数量，跨实验会复用。使用缓存前需要确认没有误用上一次的旧缓存。

## 作业队列与下一步

GPU 一次只能运行一个作业，作业按照顺序排队。依赖关系写在每条任务之后。

1. 将误分类重新归因到分类子网，确认责任通道是否明显超过随机对照。只要责任通道能够与随机对照区分开，就视为完成。
2. 基于上一步的定位结果修复误分类。先尝试抑制；如果抑制无效，再使用定向微调。依赖第 1 条。
3. 使用定向微调修复定位偏移。只解冻责任层，执行少量包含 IoU 的微调步骤。
4. 对 A、B 数据集进行多次划分，计算方差，并给出可报告的区间。依赖第 1 到 3 条。
5. 将虚检和漏检的抑制修复迁移到其他模型上，确认结果是否普遍成立。
