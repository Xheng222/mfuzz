## 目标

归因分析需要覆盖检测任务中的四类失效：虚检、漏检、误分类和定位偏移。每一类失效都需要给出责任层级特征、因果验证结论、可用修复办法和修复代价。虚检和漏检已经完成；这条工作流负责补齐误分类和定位偏移。整体验证逻辑见 docs/paper_plan/定位与修复验证框架.md。

## 已知上下文

- [决定] 方法不再限定为 training-free，以产生有效结果为准。
- [方法] A、B 两个数据集不相交，A 选责任层/通道、B 评测，判据用项目的 differential judge、不用 mAP。每一步的证据是"责任层 vs 对照层"的差分，不是绝对修复幅度。
- [结论] 虚检和漏检可以通过抑制责任通道修复，效果明显超过随机对照，因果性成立。已复核。
- [结论] 定位偏移因果性成立（剂量响应 + 对照），但抑制和单步权重调整都没有修复。已复核。
- [决定] cls 与 loc 是一对非存在性失效（loc 几何、cls 类别竞争），单层输出抑制或增强都修不了，统一用只解冻责任子网的定向微调修复（loc 用 IoU 损失、cls 用分类损失），并带非责任层对照。叙述按 2×2。完整逻辑见框架文档。
- [假设]（证据充分）误分类在单层逐通道粒度上定位不住：共享分类 conv 与末层 cls_logits 都不可分，退化归一化复核后责任组每单位退化产出的 cls 不超随机。叙述限定"本方法不能干净定位误分类"，与 E8 一致。证据与逐档数据见框架文档。保留为假设、不另设冷启动审查（负向结果、与 E8 一致、已由调度者独立复核）；cls 最终判定等第三步子网级微调给第二次机会。
- [决定] 误分类归因目标用 NMS 前 logit 尺度（已落地）：struct_attr.py 的 `_make_target` 对 cls 用 `cls_logit_target = log(p)-log1p(-p)`，抵消 sigmoid/softmax 高置信处梯度饱和。依据审计流 scores_g 结论。
- [结论]（已复核）faster_rcnn 的 cls 子网 `roi_heads.box_predictor.cls_score` 是 Linear、不在 conv_layers，逐通道机制够不到；cls 试点只能用 fcos/retinanet 的 `head.classification_head.*`。两人确认。
- [设定] cls 试点协议：A=500/B=300，score 0.5、iou 0.5、loc 0.7。末层 cls_logits 选层与 topk：fcos 91 通道用 topk=8，retinanet 819 通道用 topk=64。
- [坑] run_repair_pilot.py 不读 profile 缓存（run_baseline 每次重算 detect），换层换模型无缓存污染。
- [坑] 代码里没有 COCOeval，不要把 mAP 作为判据。
- [坑] profile 缓存 key 不含图片数量、跨实验会复用，用缓存前确认不是旧缓存。

## 作业队列与下一步

GPU 一次只能运行一个作业，作业按照顺序排队。依赖关系写在每条任务之后。

1. 误分类重新归因（已完成，可分性为负向结论）：logit 目标已落地；共享 conv.9 与末层 cls_logits 通道级都不可分。cls 通道级定位到此为止，修复转入第 2 条的统一定向微调。
2. cls 与 loc 的统一定向微调修复（当前主线）。代码已实现、本地 smoke 通过，待调度者审查后上服务器跑 GPU。设计稿见 docs/paper_plan/定向微调试点实验设计.md，五个待定项已锁定（第十节）：解冻整子网（单层留 `--single-layer` 变体）、loc 用 `1 - IoU`、cls 同时推正类压错类（只推正类留 `--no-push-down` 变体）、学习率按权重范数归一化、步数档 1/3/10/30 × 学习率档 1e-4/1e-3/1e-2。参数是（失效类, 责任子网, 损失）：loc 用 `head.regression_head` + IoU 损失，cls 用 `head.classification_head` + NMS 前 logit 分类损失。只解冻责任子网、少量多步更新，A=500/B=300 不相交，量化失效下降与代价（agree 损失 + 其他三类是否恶化）。**必须带非责任层对照**（随机层 + 最低归因层），判据是责任层修复幅度在同等代价下明显超过对照层。两类用同一协议跑、同一张表报。loc 端到端打通；cls 的 NMS 前 logit 回找路径已写（HeadLogits 半前向 + recover_cls_logit 按框 IoU 加错类通道回找 anchor 行），机制级 smoke 通过，真正能否在 COCO 上稳定回找待服务器验证。
3. 对 A、B 数据集多次划分算方差、给出可报告区间。依赖第 1、2 条全部点结果定稿。
4. 将虚检和漏检的抑制修复迁移到其他模型，确认结果是否普遍成立。
