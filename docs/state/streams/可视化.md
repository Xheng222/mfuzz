## 目标

将分散的实验产物汇总成论文需要使用的表格和图。结果需要数据完整、表达直观。必要时执行性能优化。

## 已知上下文

- [决定] 不使用热力图，改用柱状图、折线图和前沿图等形式。
- [方法] 聚合脚本统一读取 output/det/<run>/<model>/data/result.json，产出对照表和曲线。
- [坑] 性能优化只调整速度，不改变数值结果。
- [坑] matplotlib 图的标注使用英文，避免依赖中文字体。
- [设定] 实验产物布局：run_fuzz 把 cfg.run.out（如 output/det/base）当作 run 根，逐目标模型写 <run>/<model>/data/result.json，跨目标汇总图写在 <run>/_run。<run> 是配置文件名，<model> 是目标模型名。
- [设定] 检测 result.json 的 metrics 来自主循环：n_seeds、n_rounds、n_fuzzed、n_new_failures、rft、cncov_0、cncov_final、cncov_gain、n_units、n_critical、input_valid_rate、mean_s_input、lambda2/3_final、n_seeds_retired、elapsed_time，外加检测适配器补的 n_gen_saved；差分四类失效计数（miss/spurious/cls/loc 与 agree）在 extra.det.aggregate.counts。
- [坑] 本地 .venv 是符号链接到主检出，里面以可编辑方式装了主检出的 mfuzz。从工作区直接跑脚本会 import 到主检出那份 mfuzz，验证工作区代码要加 PYTHONPATH 指向工作区根。
- [坑] 工作区里 mfuzz/、scripts/ 是真实目录（各自一份），只有 output、datasets、references、.venv 是符号链接到主检出。用绝对路径写文件时要落到工作区，不要落到主检出。
