- [假设] IoU 阈值与 loc 阈值无 spec 数值定义，取值来自配置（det_oracle.py:61,100-102），只能确认参数链路一致。
- [假设] 聚类用并查集，跨模型 IoU≥阈值才 union，同模型框可经第三模型框传递连通（det_oracle.py:61-86，test 验证）。spec 未提连通传递。
- [假设] consensus 门槛 support>=2，与 spec 第四节一致（det_oracle.py:109）。
- [假设] 四类优先级 miss>cls>loc，cls 与 loc 同时成立归 cls（det_oracle.py:118-124）。spec 未规定该归并。
- [假设] loc 边界 `iou < loc_thr`（严格小于），对应 spec"低于 loc 阈值"（det_oracle.py:122-123）。
- [假设] spurious 是单点簇（support<2）里的框，用自身 box/label（det_oracle.py:125-127）；support==1 但同模型多框时逐个记 spurious。
- [假设] 同模型一簇内多框时，judge 只取最高分那个、其余丢弃不记 spurious（det_oracle.py:114-118）。建议确认不漏算失效。

### struct_attr.py（模块 2）

grad×act 归因公式与 spec 一致，未发现违反公式的偏差：

- [假设] |grad×act| 对全维求和、按桶归一化成份额（struct_attr.py:177-181），与 Day4 结构分析方法.md 第 9 行一致。
- [假设] 责任尺度取各 FPN 特征梯度绝对值和的非零最大者（:184-191），只用梯度不乘激活，与 spec 文字一致。
- [假设] 空间峰值图在责任层级做 |grad×act| 后对通道维求和取 argmax（:205），与 Day4 第 13 行一致。
- [假设] backbone 桶份额被层规模主导，spec 建议报相对 agree 的比值；该修正在下游 det_analysis.py:322-326，属设计分工。
- [结论]（已复核）归因目标对 cls/spurious/agree 用 `g.scores_g[idx]`（struct_attr.py:146），而 scores_g 是后处理后的概率、非 spec 要求的 NMS 前 logit，偏离 spec。三个检测器共用 `TorchvisionDetector.forward_graph`（det_models.py:157-178），`scores_g = out["scores"]`（:176）取自 `self.model([x])[0]`（:172）的后处理输出：faster_rcnn 走 softmax，retinanet/fcos 走 sigmoid（fcos 还乘 centerness）。两人确认：核实 worker + 调度者独立读 det_models.py。
- [假设] 用概率而非 logit 可能是误分类归因弱的成因：高置信时 sigmoid/softmax 导数 σ(1-σ) 趋零，压低 grad×act。待实验改用 logit 目标重跑、看责任通道与随机对照可分性是否改善。

### unit_coverage.py（模块 3）

账本累加与 spec 第七节、研究方案 2.1/2.2、Day3 结构分解规格.md、Day5 覆盖标定首跑.md 一致，未发现违反公式的偏差。spec 第七节只有文字描述，正式公式在 docs/materials/研究方案.md（CL/CNCov/obj_cov）。t/k 分离与分位关键度是有据的设计决策（Day3:55、coverage.py:9-18、profiler.py:_critical_mask），已核对依据，不当作 bug。以下边界与实现细节记为 [假设] 待复核：

- [假设] 覆盖判定 `norm_critical(v) > t_cov` 后 `any(dim=0)`、`covered |= hit`，只增不减（unit_coverage.py:99-104）。对应 spec"存在某测试样本使关键单元归一化激活超阈值即覆盖"（研究方案 2.2），算式与单调性一致。
- [假设] 单元粒度＝层名×调用序×通道，激活向量按布局把每个 (层,调用) 的 Conv 输出做 GAP（对 batch+空间维 mean）得逐通道标量（detection.py:_gap_vector:186-195、_build_layout:60-62）。与 Day3:53 通道级 GAP、空间维不进账本一致。
- [假设] 归一化是全局逐单元 min-max：low/high 由整个标定集累计（detection.py:147-148 torch.minimum/maximum），运行时 `(v-low)/(high-low+EPS)`（unit_coverage.py:89-97）。与 spec 第七节"按 profiling 区间做 min-max 归一化"一致。注意这与 CriticalFuzz 原版的 per-image scale（criticalfuzz/coverage.py:scale:61-74、get_critial_neuron.py:351）不同——CriticalFuzz 每张图各自 min-max，mfuzz 用全局区间，更接近 DeepGauge profiling。spec 文字采用全局区间，属有据选择。
- [假设] 频率项 `freq = (norm > t_freq).float().mean(dim=0)`（build_frequency_profile:73）／流式版 `cnts[t] += (norm>t).float()` 再除 n_ok（detection.py:_freq_pass:100-107）。spec 公式 `Freq(out(n,T)>t)` 写的是原始 out，mfuzz 在归一化后的 norm 上比较；coverage.py:9-14 说明频率与覆盖共用同一套归一化标度，是有意为之，不算偏离，但与 spec 字面 `out>t` 有标度差，记此供复核。
- [假设] 关键度＝频率达 critical_tau 分位且区间非退化：`q=quantile(freq,tau); mask=(freq>=q)&(high>low)`（profile_from_stats:59-60）。对应研究方案 2.1"关键度超阈值 τ 纳入 D_en"，这里用分位而非绝对阈值，依据见 profiler.py:_critical_mask:87-94（绝对阈值跨层不可比、分布偏 0），是有据设计。
- [假设] 边界不一致：profile_from_stats 用 `freq >= q`（含等于分位），但分类侧 profiler._critical_mask 用 `cl > thr`（严格大于）。两处都是"取分位以上"，方向一致，但等于分位时归属相反。检测 freq 是离散占比、`freq==0`/`==1` 大量打结，分位若落在打结值上，>= 与 > 选出的单元数可能差很多。建议统一两处边界约定。
- [假设] `high > low` 过滤掉恒定单元（区间退化），呼应 normalize_acts 对 high==low 的 nan_to_num 兜底（profiler.py:64-71）。spec 未明文要求，属合理边界处理。
- [假设] select_u 默认从未覆盖关键单元里取批内归一化激活最高的 U 个（unit_coverage.py:115-126），objective 取 U 单元归一化激活之和（:128-130）。对应 spec obj_cov＝∑_{n∈U} out(n,x)（研究方案 2.3 式），区别是 mfuzz 用归一化激活而非原始 out；选 U "接近阈值且信号强"在此实现为"当前归一化激活最高"，与 spec"优先接近激活阈值"方向相符但不完全等同（最高未必最接近阈值）。记此供复核。
- [假设]（可优化，本轮不改）_freq_pass 对每个 t 档都重算一遍 `(norm>t).float()` 并整向量累加，t_list 多档时重复遍历单元向量；可一次性对 t_list 做广播比较省内存带宽。属性能优化，非正确性问题。
