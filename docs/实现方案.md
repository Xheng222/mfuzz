# mfuzz 实现方案

本文是 mfuzz 的实现规格,描述当前代码的架构、模块职责和任务清单。研究动机与推导见 `docs/materials/` 下的研究方案,论文规划与逐日记录见 `docs/paper_plan/`,实验矩阵见 `docs/paper_plan/Day5/核心贡献与实验矩阵.md`。本文随实现演进更新,每完成一个任务勾选对应 checkbox。

框架经历过两个阶段。第一阶段面向图像分类,完成了差分行为、关键神经元覆盖、语义约束、联合优化四个模块(原 Phase 0 到 5,实验记录归档在 `docs/archive/`)。第二阶段把研究主线转向目标检测的结构缺陷定位,并把框架重构成任务无关的核心加任务适配层:核心循环不知道自己在测分类还是检测,任务差异全部收在适配器后面。本文描述的是重构后的形态。

## 一、设计原则

框架核心与任务解耦。核心循环只接触两样东西:覆盖单元激活向量和语义特征向量,其余前向产物对核心不透明。模型加载、种子构建、失效判定、深度分析这些任务语义都在适配器里,新任务(如 YOLO 家族、遥感检测)通过新适配器接入,核心不改。

可微优先。差分、覆盖、语义三条线索写进同一个联合目标,靠输入梯度驱动变异。各项由自己的 λ 调强弱,λ 置零即该项不计算梯度,消融自动成立,不设单独开关。

一个配置对应一个完整实验。单个 TOML 文件驱动从模型加载到最终报告的全流程,实验可以批量排队,结果可以直接横向比较。

指标全量输出且充分可视化。随迭代变化的指标画折线,最终值画柱状图或表格,不画热力图,检测图片只留少量抽查样本。

实验只在实验室服务器上跑,本地只做开发与静态检查。

## 二、技术栈

Python 3.13,uv 管理环境。PyTorch + torchvision 负责模型与自动微分。配置用 TOML 经 tomllib 填进 dataclass。loguru 日志,matplotlib 曲线,scikit-learn 聚类。开发工具 ruff(lint 与 format)、pyright(类型)、pytest(单元与冒烟)。

代码规范:完整 type hints;跨模块传 dataclass 不传裸 dict;可替换组件用抽象基类或注册表定义接口;core 不依赖上层模块。

## 四、统一数据表示

`core/records.py` 定义全框架共用的类型。失效类型固定四种:`miss`(漏检)、`spurious`(虚检)、`cls`(类别错误)、`loc`(定位偏移)。分类任务的标签翻转是 `cls` 的退化情形:锚点是整图(box 为 None),观测标签是翻转后的预测。`ConsensusAnchor` 是参考模型共识出的对象锚点(类别名 + 框 + 各模型支持度);`FailureRecord` 挂在锚点上(spurious 例外,无锚点),带语义有效性分数、来源图引用、产生轮次,轮次 -1 表示基线自然失效、非负表示变异生成的失效。`Seed` 带锚点列表、基线失效和调度统计。`RunReport` 收各轮历史曲线、指标表和任务自有数据。

类别一律用类别名比较,不用索引:各模型家族的索引约定不同(torchvision 91 类含占位项、YOLO 80 类无占位),跨模型差分必须在类别名空间进行。

## 五、框架核心

`engine/loop.py` 的 `run_loop` 是唯一主循环。启动时做一遍初始覆盖统计,然后逐轮执行:种子池按优先级选种 → 适配器组批 → 参考态前向(no_grad)→ 账本选出本轮目标单元 → 变异算子在预算内迭代 → 终态前向并更新覆盖 → 语义门控的失效判定 → 统计回写种子。每轮记录 CNCov、各类新失效、RFT、语义偏移、λ 取值,事件总线在六个关口向探针发事件。

种子池(`GenericSeedPool`)的优先级综合覆盖增益、路径新颖、缺陷历史和逐类覆盖缺口,语义不达标的种子直接沉底;变异产物不回灌成新种子,统计写回原始种子(语义偏移始终相对真正的原图度量)。连续多轮无任何产出的种子退役。

动态反馈(`optimize/feedback.py`)按滑动窗口调权:覆盖停滞上调 λ2,语义达标回落 λ3,均有上下界;初值为 0 的项视作关闭,反馈不会把它拉起来,保证消融成立。终止条件:达最大轮数、种子池耗尽、覆盖与失效增长连续双低。

## 六、三个扩展协议

**TaskAdapter**(`core/adapter.py`)。适配器负责七件循环内的事:加载模型集合与数据(setup)、构建种子(build_seeds)、标定覆盖账本(build_tracker)、组批策略(make_batches)、带图前向(forward)、差分目标(objective1)、失效判定(judge);另有四个评估钩子:补充指标、深度分析、任务图、跨目标汇总图。前向返回 `TaskForward`,核心只用其中的 unit_acts 与 v_sem,raw 字段由适配器自己消费。

**Mutator**(`optimize/mutator.py`)。联合目标 obj_total = obj1 + λ2·obj_cov − λ3·obj_sem 在算子内部合成:三路梯度各自除以 L2 范数再加权合并(量纲不同,不归一则范数大者主导),然后做 L∞ 投影梯度上升。现阶段只有 PGD 一个实现,腐蚀、几何变换等算子按同一协议平替。

**Probe**(`core/probe.py`)。探针在六个关口收事件,只读、互相独立、异常被总线捕获不中断主循环。运行结束时探针返回曲线与标量,通用报告自动画图并入表;探针也可向自己的输出子目录写任意产物。探针按注册名在配置 `[probes] enabled` 里启用。首个探针 `ood_units` 逐轮统计被推出 profiling 范围的单元数,并借账本布局表报出越界最严重的单元所在层与通道。

## 七、覆盖账本

`neurons/unit_coverage.py` 把覆盖单位抽象为"单元":检测里是层×调用序×通道,分类里是神经元。`UnitProfile` 持有布局表(单元下标可反查层名与通道)、各单元的取值区间和关键集合。激活先按 profiling 区间做 min-max 归一化再判覆盖,频率阈值(标定用)与覆盖阈值(运行时用)是两个独立参数——合用一个阈值会让初始覆盖直接饱和,这是分类阶段验证过的教训。账本提供选靶(select_u,从未覆盖单元里挑梯度信号强的)和可微覆盖目标(objective)。

分类子类 `ClsCoverageTracker` 在此之上保留全量覆盖位图(CCCov)与逐类选靶;它的选靶输出是 (B,K) 布尔掩码而基类是下标张量,两者都只被同一账本的 objective 消费,核心不感知差异。

## 八、任务适配器

**检测**(`tasks/detection.py`)。三个 torchvision 检测器(Faster R-CNN、RetinaNet、FCOS)轮换目标,其余当参考。种子构建即基线判定:跨模型 IoU 聚簇出共识锚点,四类失效判定给出每图的自然失效。前向走 `struct_attr.GraphForward`,留计算图,覆盖单元取各结构桶卷积输出的逐通道 GAP,语义向量取 FPN 各层特征拼接。差分目标是压低目标模型在锚点上的匹配分数。判定时变异图重新过差分 oracle,语义门过滤后与基线失效做同类 + IoU 的新颖性比对,新失效的变异图存 PNG 供事后归因。逐图成批(B=1,尺寸不一)。深度分析(`det_analysis.py`)在循环后执行:自然失效的逐实例结构归因(含漏检候选与深漏)、层级消融、COCO 真值核验、生成失效归因与自然/生成签名对比。

**分类**(`tasks/classification.py`)。三个分类模型(ResNet50、VGG16-BN、MobileNetV2),共识过滤建种子,统一 Seed 的锚点存共识类别。前向用旧框架的激活提取器,同尺寸样本堆成单一大批。判定走旧 triage 的四类分流,DEFECT 转成 kind="cls" 的统一记录,旧 DefectRecord 留在 extra 里供聚类沿用。profiling 复用旧 profiler(带缓存),经 UnitProfile 包装进新账本。深度分析做缺陷聚类,任务图沿用旧报告的分布、流向、聚类图。

数据集:检测的差分判定与归因用 COCO val2017,覆盖标定(criticality 频率统计)按 CriticalFuzz 的定义取训练分布大样本,从 COCO train2017 采样(`profile_dir` 与 `profile_images` 进配置;早期用 100 张 val 图标定是本地小数据集留下的习惯,只在冒烟兼容路径保留)。分类在服务器上用 imagenet-100(train 13 万做 profiling,val 5000 出种子),本地 mini-ImageNet 仅作开发用,两者经 `ImageNetLabel2Index.json` 映射回 1000 类索引。服务器 `datasets/` 下还挂了 DIOR、DOTA、RSOD、HRRSD、VOC2007 的软链接,供遥感域扩展接入。

## 九、配置体系

单一 TOML 驱动一个实验。`task` 字段判别任务;公共节 run、models、coverage、semantic、optimize、scheduler、loop、feedback、probes 由 `core/config.py` 类型化;任务私有节(`[detection]`、`[classification]`)原样传给适配器。`extends` 链式继承,变体配置只写差异。`loop.max_iterations = 0` 表示跳过反馈循环只做分析。

当前配置与实验的对应:`det/base.toml` 完整反馈循环(E1/E6 数据源),`det/struct.toml` 纯结构分析,`det/diff.toml` λ2=λ3=0 消融、`det/nofb.toml` 反馈关(E5 分组),`det/smoke.toml` 冒烟;`cls/base.toml` 分类默认,`cls/imagenet100.toml` 服务器分类实验。

## 十、入口、产物与运行方式

`scripts/run_fuzz.py` 是唯一实验入口。每个目标模型产出独立子目录:result.json(配置 + 历史 + 指标)、metrics.md、loop_curves.png(覆盖、累计失效、RFT 与语义、λ 四联图)、probe_curves.png、任务图(检测:share_ratio、ablation、nat_vs_gen;分类:分布与聚类图)、probes/ 探针产物、gen/ 新失效变异图。跨目标汇总图(failure_counts、level_distribution、gt_verdicts、det_metrics.md)落在实验根目录。

服务器运行用 `scripts/lab_run_det.sh`:自动或指定 GPU、显存不足时等待重试,nohup 后台跑。本地与服务器之间用 `scripts/sync_lab.ps1` 推拉(push 白名单 mfuzz/scripts/configs/tests,pull 白名单 output*)。历史脚本 `run_struct_analysis.py`、`run_gt_validation.py` 保留为离线工具。

## 十一、测试

`tests/` 覆盖:检测 oracle(聚簇、四类判定、漏检候选)、单元账本与布局、通用种子池调度、分类差分与分流、语义度量、梯度归一化、旧评估件。test_smoke 需要 GPU 与数据,其余纯 CPU。当前 66 个测试在服务器全部通过。

## 十二、边界与已知问题

差分只发现模型间行为差异,所有模型共犯的错误发现不了;真值核验显示部分"虚检"实为参考模型漏掉的真实小目标,部分"漏检"受 COCO 标注不完整影响,数字应读作下界。三个检测器共用同一分数阈值,失效计数里混有分数标定的成分,校准阈值对照(E3)未做。S_path 在 ε=0.03 下退化(对抗与原图的路径相似度高于同类样本间基线),路径新颖判定经 theta_path=0 关闭,修法(比类质心)留作后续。分类的归因项在 softmax 平台区近乎惰性,logit 修法未实施。这些分类阶段的实测细节归档在 `docs/archive/` 与 git 历史(本文 2026-06-11 之前的版本)。
