# mfuzz 实现方案

本文是 mfuzz 的实现规格，记录当前代码的架构、模块职责和任务清单。研究动机与推导见 `docs/materials/` 下的研究方案。论文规划与逐日记录见 `docs/paper_plan/`。实验矩阵见 `docs/paper_plan/Day5/核心贡献与实验矩阵.md`。本文随着实现进展更新；每完成一个任务，就勾选对应 checkbox。

框架经历过两个阶段。第一阶段面向图像分类，完成了差分行为、关键神经元覆盖、语义约束和联合优化四个模块。原 Phase 0 到 Phase 5 的实验记录已经归档在 `docs/archive/`。第二阶段把研究方向转向目标检测中的结构缺陷定位，并把框架重构为任务无关核心加任务适配层。核心循环不需要知道当前任务是分类还是检测，任务差异都由适配器处理。本文描述的是重构后的框架形态。

## 一、设计原则

框架核心与任务解耦。核心循环只接触覆盖单元激活向量和语义特征向量，其他前向产物对核心不透明。模型加载、种子构建、失效判定和深度分析等任务语义，都由适配器实现。新任务，如 YOLO 家族和遥感检测，通过新增适配器接入，核心不需要修改。

框架优先使用可微机制。差分、覆盖和语义三类信号写入同一个联合目标，通过输入梯度驱动变异。每一项由自己的 λ 控制强弱。λ 置零时，该项不计算梯度，对应消融不需要额外开关。

一个配置对应一个完整实验。单个 TOML 文件驱动从模型加载到最终报告的全流程。实验可以批量排队，结果可以直接比较。

指标需要完整输出，并提供足够的可视化。随迭代变化的指标使用折线图，最终值使用柱状图或表格。文档和图表不使用热力图。检测图片只保留少量抽查样本。

实验只在实验室服务器上运行。本地只用于开发与静态检查。

## 二、技术栈

项目使用 Python 3.13，并用 uv 管理环境。PyTorch 和 torchvision 负责模型与自动微分。配置使用 TOML，并通过 tomllib 转换为 dataclass。日志使用 loguru，曲线使用 matplotlib，聚类使用 scikit-learn。开发工具包括 ruff（lint 与 format）、pyright（类型检查）和 pytest（单元测试与冒烟测试）。

代码规范如下：完整书写 type hints；跨模块传递 dataclass，不传递裸 dict；可替换组件使用抽象基类或注册表定义接口；core 不依赖上层模块。

## 四、统一数据表示

`core/records.py` 定义全框架共用的类型。失效类型固定为四种：`miss`（漏检）、`spurious`（虚检）、`cls`（类别错误）和 `loc`（定位偏移）。分类任务的标签翻转是 `cls` 的特例：锚点是整图（box 为 None），观测标签是翻转后的预测。`ConsensusAnchor` 表示参考模型共识出的对象锚点，包含类别名、框和各模型支持度。`FailureRecord` 关联到锚点；`spurious` 是例外，它没有锚点。记录中还包含语义有效性分数、来源图引用和产生轮次。轮次 -1 表示基线自然失效，非负轮次表示变异生成的失效。`Seed` 保存锚点列表、基线失效和调度统计。`RunReport` 收集各轮历史曲线、指标表和任务自有数据。

类别比较一律使用类别名，不使用索引。各模型家族的索引约定不同，torchvision 的 91 类包含占位项，YOLO 的 80 类没有占位项。因此，跨模型差分必须在类别名空间中完成。

## 五、框架核心

`engine/loop.py` 中的 `run_loop` 是唯一主循环。启动时先执行一次初始覆盖统计，然后逐轮执行以下流程：种子池按优先级选择种子 → 适配器组批 → 参考态前向（no_grad）→ 账本选出本轮目标单元 → 变异算子在预算内迭代 → 终态前向并更新覆盖 → 语义门控的失效判定 → 统计回写种子。每一轮都会记录 CNCov、各类新失效、RFT、语义偏移和 λ 取值。事件总线在六个关口向探针发送事件。

种子池 `GenericSeedPool` 的优先级综合覆盖增益、路径新颖性、缺陷历史和逐类覆盖缺口。语义不达标的种子直接降到最低优先级。变异产物不作为新种子加入种子池，统计写回原始种子。语义偏移始终相对真正的原图计算。连续多轮没有任何产出的种子会退出后续调度。

机制与评测分层是核心设计原则。调度只使用上述过程信号。缺陷身份去重等产出指标只在事后评测中计算，即检测适配器的 analyze 阶段，对应传统 fuzzing 中的 unique crashes。它们不反馈到调度或变异中。如果把产出指标写入机制层，就等于把待检验命题"通用反馈能否产出更多独特缺陷"直接变成优化目标，使检验失去独立性。循环内逐轮记录的"新失效"是触发记录数，只对种子的自然基线去重。独特缺陷数在报告中另列。

动态反馈在 `optimize/feedback.py` 中实现。它按滑动窗口调整权重：覆盖停滞时上调 λ2，语义达标回落时下调 λ3，并且两项都有上下界。初值为 0 的项视为关闭，反馈不会重新启用该项，因此消融成立。终止条件包括达到最大轮数、种子池耗尽，以及覆盖与失效增长连续处于低位。

## 六、三个扩展协议

**TaskAdapter**（`core/adapter.py`）。适配器负责循环内的七件事：加载模型集合与数据（setup）、构建种子（build_seeds）、标定覆盖账本（build_tracker）、组批策略（make_batches）、带图前向（forward）、差分目标（objective1）和失效判定（judge）。它还提供四个评估钩子：补充指标、深度分析、任务图和跨目标汇总图。前向返回 `TaskForward`。核心只使用其中的 unit_acts 与 v_sem，raw 字段由适配器自行处理。

**Mutator**（`optimize/mutator.py`）。联合目标 obj_total = obj1 + λ2·obj_cov − λ3·obj_sem 在算子内部合成。三路梯度各自除以 L2 范数后再加权合并；这些梯度量纲不同，如果不归一化，范数大的项会主导结果。合并后执行 L∞ 投影梯度上升。现阶段只有 PGD 一个实现。腐蚀、几何变换等算子可以按同一协议替换。

**Probe**（`core/probe.py`）。探针在六个关口接收事件，只读、相互独立。探针异常会被事件总线捕获，不会中断主循环。运行结束时，探针返回曲线与标量，通用报告自动画图并写入表格。探针也可以向自己的输出子目录写任意产物。探针按注册名在配置 `[probes] enabled` 中启用。首个探针 `ood_units` 逐轮统计超出 profiling 范围的单元数，并借助账本布局表报告越界最严重单元所在的层与通道。

## 七、覆盖账本

`neurons/unit_coverage.py` 把覆盖单位抽象为"单元"。检测任务中的单元是层 × 调用序 × 通道，分类任务中的单元是神经元。`UnitProfile` 保存布局表、各单元取值区间和关键集合。布局表可以由单元下标反查层名与通道。激活先按照 profiling 区间做 min-max 归一化，再判定覆盖。研究方案里频率 Freq 与覆盖目标 obj_cov 的公式写作原始激活 out，实现统一在归一化后的激活 ĉ 上计算这些量：各层激活的量纲差异大，固定阈值直接作用在原始激活上，会让部分层几乎全激活、部分层几乎不激活；归一化之后，阈值对所有层都表示爬到自身取值区间的相对高度，含义一致。频率阈值用于标定，覆盖阈值用于运行时判断，这两个参数相互独立。合用一个阈值会让初始覆盖直接饱和，这是分类阶段已经验证过的教训。账本通过 select_u 从未覆盖单元中选择梯度信号强的目标，同时提供可微覆盖目标 objective。

分类子类 `ClsCoverageTracker` 在此基础上保留全量覆盖位图 CCCov 与逐类目标选择。它的输出是 (B,K) 布尔掩码，基类输出是下标张量。两者都只由同一账本的 objective 使用，核心不感知差异。

## 八、任务适配器

**检测**（`tasks/detection.py`）。三个 torchvision 检测器 Faster R-CNN、RetinaNet 和 FCOS 轮换作为目标模型，其余模型作为参考模型。种子构建同时完成基线判定：跨模型 IoU 聚簇得到共识锚点，四类失效判定给出每张图的自然失效。前向使用 `struct_attr.GraphForward` 并保留计算图。覆盖单元取各结构桶卷积输出的逐通道 GAP，语义向量取 FPN 各层特征拼接。差分目标是压低目标模型在锚点上的匹配分数。判定时，变异图重新经过差分 oracle，语义门过滤后，再与基线失效做同类 + IoU 的新颖性比对。新失效的变异图保存为 PNG，供事后归因使用。检测按图成批，B=1，允许尺寸不一致。深度分析在 `det_analysis.py` 中执行，发生在循环之后，包含自然失效的逐实例结构归因（含漏检候选与深漏）、层级消融、COCO 真值核验、生成失效归因，以及自然/生成结构分布对比。

**分类**（`tasks/classification.py`）。分类任务使用三个模型：ResNet50、VGG16-BN 和 MobileNetV2。适配器通过共识过滤构建种子，统一 Seed 的锚点保存共识类别。前向沿用旧框架的激活提取器，同尺寸样本堆成单一大批。判定沿用旧 triage 的四类分流，DEFECT 会转换成 kind="cls" 的统一记录，旧 DefectRecord 保存在 extra 中供聚类沿用。profiling 复用旧 profiler，并保留缓存；结果经 UnitProfile 包装后进入新账本。深度分析执行缺陷聚类，任务图沿用旧报告中的分布图、流向图和聚类图。

数据集方面，检测的差分判定与归因使用 COCO val2017。覆盖标定，即 criticality 频率统计，按 CriticalFuzz 的定义取训练分布大样本，并从 COCO train2017 采样。`profile_dir` 与 `profile_images` 写入配置。早期使用 100 张 val 图标定，是本地小数据集留下的习惯，只在冒烟兼容路径中保留。分类任务在服务器上使用 imagenet-100，其中 train 13 万张用于 profiling，val 5000 张用于生成种子。本地 mini-ImageNet 只用于开发。两者都通过 `ImageNetLabel2Index.json` 映射回 1000 类索引。服务器 `datasets/` 下还挂载了 DIOR、DOTA、RSOD、HRRSD 和 VOC2007 的软链接，供遥感域扩展接入。

## 九、配置体系

单一 TOML 驱动一个实验。`task` 字段判别任务。公共节 run、models、coverage、semantic、optimize、scheduler、loop、feedback 和 probes 由 `core/config.py` 类型化。任务私有节 `[detection]` 和 `[classification]` 原样传给适配器。`extends` 支持链式继承，变体配置只写差异。`loop.max_iterations = 0` 表示跳过反馈循环，只执行分析。

当前配置与实验对应关系如下：`det/base.toml` 对应完整反馈循环和 E1/E6 数据源；`det/struct.toml` 对应纯结构分析；`det/diff.toml` 对应 λ2=λ3=0 消融；`det/nofb.toml` 对应反馈关闭的 E5 分组；`det/smoke.toml` 用于冒烟测试；`cls/base.toml` 是分类默认配置；`cls/imagenet100.toml` 是服务器分类实验配置。

## 十、入口、产物与运行方式

`scripts/run_fuzz.py` 是唯一实验入口。每个目标模型产出独立子目录，包含 result.json（配置 + 历史 + 指标）、metrics.md、loop_curves.png（覆盖、累计失效、RFT 与语义、λ 四联图）、probe_curves.png、任务图、probes/ 探针产物和 gen/ 新失效变异图。检测任务图包括 share_ratio、ablation 和 nat_vs_gen。分类任务图包括分布图与聚类图。跨目标汇总图保存在实验根目录，包括 failure_counts、level_distribution、gt_verdicts 和 det_metrics.md。

服务器运行使用 `scripts/lab_run_det.sh`。脚本支持自动或指定 GPU，显存不足时等待重试，并使用 nohup 后台运行。本地与服务器之间使用 `scripts/sync_lab.ps1` 推拉。push 白名单包含 mfuzz、scripts、configs 和 tests，pull 白名单包含 output*。历史脚本 `run_struct_analysis.py` 和 `run_gt_validation.py` 作为离线工具保留。

## 十一、测试

`tests/` 覆盖检测 oracle（聚簇、四类判定、漏检候选）、单元账本与布局、通用种子池调度、分类差分与分流、语义度量、梯度归一化和旧评估件。test_smoke 需要 GPU 与数据，其余测试只需要 CPU。当前 66 个测试在服务器全部通过。

## 十二、边界与已知问题

差分只能发现模型间行为差异，无法发现所有模型共同犯下的错误。真值核验显示，部分"虚检"其实是参考模型漏掉的真实小目标，部分"漏检"受 COCO 标注不完整影响，因此数字应读作下界。三个检测器共用同一分数阈值，失效计数中混有分数标定因素。校准阈值对照 E3 尚未完成。S_path 在 ε=0.03 下退化，对抗图与原图的路径相似度高于同类样本间基线。路径新颖判定已经通过 theta_path=0 关闭，后续应改为与类质心比较。分类归因项在 softmax 平台区几乎不起作用，后续应改用 logit 目标。这些分类阶段的实测细节归档在 `docs/archive/` 与 git 历史中，即本文 2026-06-11 之前的版本。
