# Day 5 续：差分判定的真值核验

日期 2026-06-11。微观输出落地之后，按既定工作顺序做了第一项核验：把差分 oracle 在 200 张 COCO val 图上判出的全部实例，逐条对照 `instances_val2017.json` 的真值标注，产出"oracle 判定 × 真值裁决"的混淆表。脚本是 `scripts/run_gt_validation.py`，完全离线，只依赖结构分析落盘的逐实例 JSON 和标注文件。结果在 `output_det/gt_validation/`，逐实例裁决带原 viz 路径，可以回到标注图上人工复核。

## 裁决标准

IoU 阈值与差分判定时一致（聚簇 0.5，定位 0.7）。每类判定的真值裁决如下。spurious 看检测框有没有同名真值框支持：有记 supported_by_gt，位置有物体但类别不同记 gt_label_differs，完全没有真值重叠记 confirmed。miss 先核 consensus 对象本身：代表框与同名真值框达标记 confirmed（真值确认漏检），无真值重叠记 consensus_unsupported（consensus 判定本身不被真值支持）。cls 用真值类别当裁判，分成 consensus_right、model_right、both_wrong、no_gt_object 四种。loc 由 consensus 锚定物体身份后量检测框相对真值框的 IoU：低于 0.7 记 confirmed，达标记 gt_loc_ok。agree 抽样组当对照，核它相对真值的正确率。iscrowd 的真值框参与匹配。

## 读数

agree 对照组的真值正确率是 91% 到 94%。跨模型一致的检测基本就是对的，这给 agree 当归因份额的归一化基线提供了依据，也说明 consensus 机制本身没有系统性偏差。

spurious 的真值确认率是 72% 到 82%，是四类失效里最可靠的判定。faster_rcnn 有 170 个（25%）"虚检"被真值支持：物体真实存在，只是另外两个模型都没检出。这批被支持的检测比确认虚检更小（中位面积 1188 对 1785）、分数更高（中位 0.79 对 0.68）。Day 5 抽查发现的冰箱个例在规模上成立：faster_rcnn 的 P2 细尺度既产出真实虚检，也找到其它架构漏掉的真实小目标。论文里差分计数和真值过滤后的计数要分开报。

miss 的真值确认率分化：retinanet 只有 51%，另有 138 个 consensus_unsupported。对后者抽查标注图发现，相当一部分是真实存在但 COCO 没有标注的物体——桌上的盆栽、灌木后面被遮挡的卡车，frcnn 和 fcos 框得很准、分数 0.7 以上。COCO 标注不完备是已知问题，所以 51% 是真值能确认的下界，不是 oracle 的错误率。两个子集的特征也不同：真值确认的漏检更小（中位面积 1918 对 2855）、同伴分数更高（中位 0.91 对 0.75）。同伴分数可以当 consensus 可信度的代理信号。

cls 是四类里最弱的判定。三模型投票二比一，真值站在 consensus 一边的只有 24% 到 48%，faster_rcnn 上真值更常站在模型自己一边（model_right 10 对 consensus_right 5）。两票多数不足以裁决类别，论文里 cls 的差分计数只能当分歧信号用，模式层面的主张要靠真值或更多模型。好在 cls 计数本来就少。

loc 有三到五成实例匹配不到真值对象（no_gt），能匹配上的实例里确认率过半。loc 判定依赖 consensus 代表框的精度，真值核验后这条判定的可用子集明显变小。

## 关键结论：结构签名对真值裁决不敏感

把每个目标模型的失效实例按真值裁决分组，重新计算结构签名，三条架构签名全部在真值确认的子集上成立：

| 签名 | 全量数字 | 真值确认子集 | 无真值支持子集 |
|---|---|---|---|
| faster_rcnn 虚检责任尺度 P2 | 64% | 63%（306/489） | supported_by_gt 也是 69% P2 |
| retinanet 漏检 fpn.inner / fpn.layer 比值 | 2.5–3.2× | 3.33× / 2.78× | 3.33× / 2.89× |
| fcos 虚检责任尺度 P3 | 58% | 52%（61/117） | supported_by_gt 79% P3（19/24） |
| fcos 定位 head.reg 比值 | 3.62× | 3.51× | no_gt 3.69×，gt_loc_ok 3.91× |

签名数字在确认子集和未确认子集之间几乎没有差别。结构归因量的是模型内部的处理通路，不依赖触发实例相对真值是否成立。这对论文是双重利好：主发现（架构特定的结构失效签名）经过真值清洗后存活；同时归因方法本身的稳定性得到一次独立检验。

## 对第三幕设计的影响

这次核验等于把"换裁判"提前演练了一遍：诱发手段不变（自然差分分歧），裁判从跨模型一致性换成真值，结论不变。第三幕的正面验证再把诱发手段也换掉（腐蚀变换），就构成完整的双重独立验证。另外两条设计调整：cls 的模式主张降级或者依赖真值裁决；miss 的报告把 consensus_unsupported 单独列出，并说明 COCO 标注不完备导致它是混合裁决（真实未标注物体与集体误检混在一起），不能简单计入 oracle 错误。
