# Day 5：论文故事与验证设计

日期：2026-06-10。全量结构分析出数之后，经讨论确定了论文的叙事结构、验证设计和接下来的工作顺序。本文记录这次讨论的结论，作为实验矩阵定稿前的设计依据。

## 三步叙述

论文按三步展开。第一步，提出一个动态反馈驱动的框架。这个框架发现检测模型的失效，并把失效定位到结构位置。第二步，用多种消融验证框架设计合理：框架能稳定产出数据和结果，观察式证据与干预式证据能够相互印证。这一步证明框架内部逻辑成立，但还不能证明它有实际作用。第三步，用外部的、独立于框架自身的手段，证明框架找到的缺陷确实存在，并且我们的方法更好。

前两步是必做项。第三步需要谨慎推进。原因是当前还没有一个完全可信的失效模式判定方案。在逐实例的微观证据建立起来之前，模式层面的主张缺少足够支撑。

## 第一步的必要前提

结构定位部分已经完成全量运行，见同目录的框架适配文档。失效发现部分还停留在分类版。要把反馈循环迁移到检测任务，需要完成以下改造：hooks 的多次调用累积，使神经元单位变为层×尺度×通道；profiling 改用 NMS 前类别 logit 作为归因目标；obj_1 改写为 consensus 对象匹配分数的偏离；语义项的 v(x) 换成 backbone 或 FPN 特征；engine 的 Seed 改为共识对象集合。机制不变，变化的是目标和数据结构。

## 第二步的消融分组

分类版的消融基础可以直接继承。configs 里的 diff、diff_cov、diff_sem、full 已经是现成分组，λ2/λ3 置零、动态反馈开关、α 切频率与归因都不需要重新实现。检测版新增三组结构分析特有消融：观察式归因与干预式消融的印证（已有）、归因份额相对 agree 对照的比值（已有）、pilot 到全量的稳定性（已有）。还需要补一组按模型校准分数阈值的对照，用于回应三模型分数标定不同的问题。

另有一组明确有价值的实验：自然失效与 fuzzing 生成失效的结构分布对比。如果生成失效落在与自然失效相同的结构位置上，说明框架找到的是真实薄弱点；如果生成失效落在新位置，说明反馈驱动发现了静态分析没有覆盖的区域。两种结果都有解释价值。

## 第三步的外部验证与修复验证

验证必须面向结构模式，因为论文主张关注结构性的缺陷分布，而不是单个失效实例。验证分为两条。

外部诱发验证：用独立的失效诱发手段，在同一批模型上诱发失效，再运行同一套结构归因，观察结构定位结果是否收敛。诱发手段选择 COCO-C 风格的腐蚀变换（模糊、噪声、天气），或按真值属性筛出的困难子集（小目标、遮挡）。这个设计的主要好处是，腐蚀图像带真值，失效判定可以直接使用真值，不依赖差分 oracle。如果诱发手段和裁判都更换后，结构定位结果仍然收敛，一次实验可以同时支持 oracle 可靠性和结构结论真实性。比较时必须使用条件分布，即给定失效类型后再看结构分布，因为不同诱发手段产生的失效类型比例本来就不同。

修复验证：按缺陷类型做针对性修复，验证错误率是否下降。设计关键在对照组：只解冻责任结构桶微调，对比同参数量、同步数下只解冻一个非责任桶微调。如果前者对该类失效的削减显著更多，并且整体 mAP 不退化，定位的因果性才算成立。验证端使用双重标准：本项目差分框架的计数，加上外部诱发方案下的计数。这条实验的主要成本在微调，放到最后进行，前提是结构定位结果已经可信。

## 当前瓶颈：报告过于宏观

当前输出报告只有聚合指标，缺少微观原始数据。JSON 中的逐实例记录有图名、失效类型、consensus 类别、责任层级、落框标志和逐桶份额，但没有框坐标和分数，没有 consensus 簇上下文（其他模型在同一位置判了什么），没有空间峰值坐标，也没有可视化。结果是拿到聚合表后，无法回到任何一个具体失效上检查"这真的是缺陷吗"。

需要做的升级包括：逐实例记录补全检测框、分数、簇内全部模型的检测；每个失效实例保存一张标注图，画出目标模型的框、consensus 代表框、其他模型的框、责任层级的梯度×激活热力图与峰值位置，并按失效类型分文件夹存放。有了微观证据之后，先人工抽查一批实例，确认 oracle 判定和归因指向是否可信。可靠性要从实例层面建立，不能只依赖声明。

这项升级当天已经完成，并重新运行了全量实验。逐实例 JSON 已经带齐框坐标、分数、簇上下文、峰值坐标和标注图路径，深漏单独入档。每个目标模型每类失效最多保存 30 张标注图，位置在 `output_det/struct_analysis/<目标>/viz/<类型>/` 下。初步抽查给出一个重要提醒：差分判定中的 spurious 表示"不被其他模型支持"，不等于"相对现实是错的"。有的 spurious 框住的物体真实存在，只是另外两个模型没有检出。这正是第三步需要真值核验的原因。差分 oracle 的判定和相对真值的判定需要分开陈述。

## 结构归因的模块化方向

结构归因最终做成独立模块，放在 `evaluate/` 下。它不关心失效从哪里来。自然差分、fuzzing 生成、腐蚀诱发的失效，都可以作为输入的失效实例集合，加上目标模型，输出结构分析报告。当前的 struct_attr 模块加 run_struct_analysis 入口是它的雏形。等接口在几种输入来源上稳定后，再正式化为独立模块。当前先确认方向可行。

## 工作顺序

第一步，补全微观输出并人工抽查，建立失效判定与归因的可信度。这是后续工作的基础。第二步，适配检测版 profiling 与 fuzzing，让第一步中的反馈循环运行起来。第三步，做外部诱发验证，即腐蚀诱发 + 真值裁判 + 结构结论收敛。这一步不依赖微调，成本较低。第四步，做修复验证，等结构定位结果可信后再投入。实验矩阵文档按这个顺序安排。核心贡献沿着三步叙述确定为两条：动态反馈驱动的检测失效发现与结构定位一体化框架；目标模型的结构缺陷定位证据。

后记（2026-06-11）：第一步在次日完成了系统化。真值核验把 200 张图的全部差分判定逐实例对照 COCO 标注，agree 对照组正确率为 91% 到 94%，三条结构结论在真值确认子集上全部保持成立，相当于提前演练了第三步中"更换裁判"的环节。结论与教训见同目录 `真值核验.md`。核心贡献与实验矩阵随后正式确定，见 `核心贡献与实验矩阵.md`。
