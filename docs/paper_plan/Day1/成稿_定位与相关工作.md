# Day 1 成稿：定位与相关工作

本文是 Day 1 的最终归纳。它基于两份深度研究报告（见 `references/`）和 Codex 的逐条核实稿（`Day1_调研核实稿.md`）写成。两份深度研究报告负责广度发现，核实稿负责原文核实与去重，本文负责把结论整理成可以写入论文导论和相关工作章节的判断。文献条目编号沿用核实稿（A 到 H 组）。

## 一、核心结论：研究空白成立

两份深度研究各自独立检索，再经 Codex 对照原文核实，三份材料指向同一个判断：现有公开文献中，没有一篇工作把目标检测的失效类型系统回溯到模型内部的结构位置。这个结论由多个来源支持，比单一报告的判断更可靠。

现有工作已经提供了四类基础，但还没有把它们组合成本文所需要的问题。

- 检测错误标签已经成熟。Hoiem（E-01）、LRP（E-02）和 TIDE（E-03）能把检测错误分解成定位、分类、背景、重复、漏检等类型，并量化各类错误对 AP 的影响。但它们都停在输出层，不解释错误发生时模型内部发生了什么。
- 检测测试生成已经成熟。MetaOD（D-01）、ObjTest（D-03）和自适应变质测试（D-04）能在 oracle 不完整时大量暴露检测失败。但它们把检测器当黑盒或浅白盒，目标是"高效发现失败"，不是"失败来自哪个结构"。
- 检测结构坐标系已经清楚。FPN（H-02）给出尺度轴，RetinaNet（H-03）给出分类分支与回归分支轴，FCOS（H-04）让空间位置直接对应输出责任。Double-Head（H-09）、TSD（H-10）、TOOD（H-11）已经证明分类和定位在 head 内承担不同功能。但这些工作服务于架构改进，不对失败样本做结构归因。
- 归因工具已经齐全。LRP、Integrated Gradients、Grad-CAM、CRP（G 组）和 Network Dissection（G-04）能把证据追溯到层、通道、概念和输入区域；D-RISE（G-08）专为检测设计了显著图。但它们不以"漏检、虚检、定位偏移、类别错误"为因变量，也不建立检测结构坐标系。

最接近本文方向的单篇工作是检测层级剪枝（G-10）。它用梯度乘激活给检测网络各层打贡献分。但它的目标是全局剪枝，会把成百上千张图在某层的表现求均值，因此抹掉了单张图发生漏检或定位偏移时的运行时结构异常，无法直接用于缺陷定位。

## 二、研究空白的准确表述

写入论文导论的一句话：

> 现有检测诊断方法能说明检测错误属于什么类型，检测架构研究能说明结构模块承担什么功能，解释方法能说明某个输出依赖哪些输入区域或概念，但还缺少把具体的检测失效类型系统回溯到检测模型内部结构位置的测试与分析框架。

判断空白成立需要四个条件，现有工作没有一篇同时满足：以检测失效为对象，而不是以分类错误或通用鲁棒性为对象；用漏检、虚检、定位偏移、类别错误作为统一标签；读取模型内部激活、梯度或结构信号；把失效统计到 backbone 阶段、FPN 尺度、检测头分类或回归分支、特征图空间区域这些结构位置。

## 三、方法谱系：本文的来源与推进

论文需要说明，本文不是凭空提出，而是沿着几条成熟线索继续推进。

相对 DeepXplore（A-01）。差分 oracle、白盒覆盖反馈和梯度驱动变异这三件事，是 DeepXplore 首次合在一起的。本文的分类版框架仍属于这条谱系。本文的推进有两层：先把覆盖对象从全量神经元缩小到关键单元，并加入语义约束，这一步在分类版中已经完成；再把任务从分类迁移到检测，把目标从"发现缺陷"改为"定位缺陷的结构来源"，这是本文新增的部分。

相对 CriticalFuzz（C-01）。CriticalFuzz 是关键神经元覆盖的直接来源。它证明了"关键单元优先"能成为独立的方法贡献，而不只是工程优化，并且把 profiling 阈值和运行时覆盖阈值分成两个独立参数。分类版已经吸收这一点。CriticalFuzz 仍局限于分类任务，没有把缺陷映射到结构轴。本文把关键神经元概念扩展到检测的多尺度、多分支结构，并把它作为结构归因的基础表示。

相对覆盖有效性争议（B-05 Harel-Canada、B-09 NLC 一类工作）。这些工作证明，提高普通神经元覆盖不必然提升缺陷发现能力，为本文不使用全局覆盖、改用关键覆盖提供了理由。本文继续推进这条批评：覆盖不仅要按重要性筛选，还要按检测的尺度、分支和空间位置定义与统计。

相对 TIDE 与 Hoiem（E-03、E-01）。本文直接采用它们的错误分解作为失效标签。TIDE 的六类错误（classification、localization、both、duplicate、background、missed）与本文四类的对应关系是：missed 对应漏检，background 加 duplicate 对应虚检，localization 对应定位偏移，classification 对应类别错误。both（分类定位都错）需要单列还是拆开，留到 Day 2 定义 oracle 时决定。本文的贡献是把它们的输出层 taxonomy 继续映射到内部结构轴。

相对检测解释工作（G-08 D-RISE、G-09 CRP、G-04 Network Dissection）。它们提供归因工具箱：D-RISE 能说明图像哪片区域影响检测输出，CRP 能同时回答 where 和 what，Network Dissection 能说明某个单元代表什么。本文把这套工具用于自己的问题：以失效类型为因变量，配套一套检测结构坐标系，回答"错误来自 FPN 哪个尺度或 head 哪个分支"，而不只是回答"图像哪片像素重要"。

## 四、候选创新点

1. 主要贡献：失效类型到结构位置的缺陷定位。把检测的四类失效归因并统计到 backbone 阶段、FPN 尺度、检测头分类或回归分支、特征图空间区域，回答"检测模型的缺陷在结构上集中在哪里"。这是论文对 gap 的正面回答。
2. 支撑方法：检测版差分 oracle 加四类失效统一标签。把分类的共识标签机制改造成检测中的 IoU 匹配、类别共识和分数共识，并按 TIDE 谱系定义四类失效。这是主要贡献成立的前提。
3. 支撑方法：关键神经元覆盖向检测多尺度、多分支结构的扩展。把关键神经元和覆盖率重新定义到尺度、分支和空间区域上，给结构归因提供内部表示。
4. 辅助内容：内部反馈联合优化框架从分类到检测的迁移。把差分、关键覆盖和语义约束的联合优化迁移到检测任务。这一项单独看新意有限，主要作为结构定位方法的基础。

第 1 项是论文最重要的贡献，第 2、3 项支撑第 1 项，第 4 项是已有框架的迁移。论文叙事应让结构定位成为主要内容，框架作为方法支撑。

## 五、最该对标的近邻工作

这几篇是关键参照。写相关工作时，需要逐一说明它们的边界，以及本文做了什么不同。

- TIDE（E-03）：失效标签的直接来源和对照基线。它停在输出层错误分解，本文把分解结果映射回结构。
- Double-Head（H-09）、TSD（H-10）、TOOD（H-11）：最强近邻。它们已经承认并分析了分类分支与回归分支承担不同功能，这正是本文要使用的结构轴。区别在于，它们的目标是改进 detector 设计，不对失败样本做结构归因。这组要重点区分，否则容易被质疑创新性。
- TridentNet（H-13）、YOLOF（H-14）：尺度轴的近邻。它们证明尺度是检测结构分析中的真实变量，但停在设计消融，不统计失败集中在哪个尺度。
- D-RISE（G-08）：检测解释的代表，也是本文归因方法的对照。它停在输入空间显著图，本文做内部结构定位。
- 检测层级剪枝（G-10）：技术上最接近层级归因，但目标是全局静态剪枝，并且对样本求均值，无法诊断单张图的运行时失效。本文与它的关键区别是失效驱动且逐样本。

## 六、引用更正备忘

Codex 核实出的错误，写作时不要沿用报告原文：

- Surprise Adequacy（B-02）作者是 Jinhan Kim，不是 ChatGPT 报告写的 Jihye Kim。
- "Is Neuron Coverage a Meaningful Measure"（B-05）作者是 Harel-Canada 等，不是 Gemini 报告写的 Meng Yan 等。
- NLC（B-09）正式出处是 Yuan 等，ICSE 2023。
- MetaOD（D-01）正式题名是 Metamorphic Object Insertion，arXiv 预印本题名才是 Metamorphic Testing for Object Detection Systems。
- ReIC（D-06）主任务是图像描述，不是目标检测，Gemini 报告归错了类，只能当遮挡变异的弱参考。
- NSS（C-03）正式出处是 TOSEM 2024，不是报告里的 FSE 2023 或 ASE 2024。
- 检测层级剪枝（G-10）题名是 Layer-Wise Pruning，不是 Gemini 报告写的 Structured Pruning。
- 开放词汇鲁棒性（F-07）题名应按 Open-Vocabulary Object Detectors: Robustness Challenges under Distribution Shifts，不是报告里的 Robustness Evaluation on COCO-O 等。
- SNBF-YOLO（H-20）是 2025 年 Scientific Reports，不是 Gemini 报告写的 2024。

另外几篇标年份 2026 或仍是投稿的工作（B-10、E-06、F-08、F-09、G-10），引用前要确认正式发表状态。投稿状态的工作，如 F-09，不宜作为正式主引用。
