# 路线图

本文件记录 mfuzz 当前阶段的多日计划，是调度者开工时核对方向的依据。它处在最上层，给出总的目标与顺序。每条流的具体待办，放在 docs/state/streams/ 各自的作业队列里。某一天实际推进哪几条，由调度者写进自己调度文件的今日计划。三者各管一层，不重复抄写。

## 当前阶段：Day8 到 Day13

这一阶段的总目标，是把归因分析从虚检、漏检扩展到全部四类失效，把缺陷的定位与修复讲成一个完整的故事，同时推进论文写作、产出结构化的可视化、并对整个项目做一轮代码审计。方法不再限定为免训练。只要能做出效果，训练手段也可以采用。因此定位偏移的定向微调进入本阶段的工作范围，不再留作展望。

工作沿四条流并行展开。实验流补齐误分类与定位偏移的归因和修复。写作流先完成研究现状一章，再补其余章节的大纲。可视化流把分散的实验产物汇总成论文要用的表和图。审计流逐个模块对照实现方案，确认框架的行为与定义一致。四条流当中，实验流受 GPU 串行的限制，其余三条属于桌面工作，可以真正并行。每天的安排尽量让各流的工作量与时间相当。

## 实验流的主线

实验流先处理误分类。之前的归因挂在回归头上，责任通道与随机通道分不开，怀疑是归因的层选错了。第一步把归因换到分类子网，观察责任通道能否明显超过随机对照。这一步同时回答误分类能否定位到单层。定位一旦成立，再尝试修复，先用抑制，抑制不动就改用定向微调。

定位偏移的因果性此前已经用剂量响应验证，但抑制和单步改权重都修不动它。本阶段改用定向微调来修：只解冻责任层，用带 IoU 的几步微调，在不相交的评测集上观察定位误差是否下降、代价有多大。

四类失效都得出结论之后，把它们汇成一张统一的表。每一类写清责任层级的特征、因果验证的结论、可用的修复办法以及它的代价。最后补两件事：多次划分数据跑出方差，给出可以报告的区间；把虚检、漏检的修复推广到其它模型，验证它是否普遍成立。

## 写作、可视化、审计三流

写作流先做研究现状的文献调研，分两批进行。第一批覆盖覆盖率引导的测试、对神经元覆盖率有效性的批评、以及差分与蜕变测试。第二批覆盖结构归因与可解释性、以及不靠训练的修复与模型编辑，重点说清我们与 DeepFault 这类先定位可疑神经元再修复的工作的差别。调研之后成文，再补其余章节的大纲。

可视化流先写一个汇总脚本，统一读取各次实验的 result.json，产出对照表与曲线。等实验流的误分类与定位结果出来，再做四类指标的统一表和图。所有图都不使用热力图。

审计流逐个模块对照实现方案检查：差分预言的判定、结构归因的公式、覆盖账本的累计、标定阈值的使用、主循环与适配层的分层。发现的偏差先记成假设，核实之后升成结论。一旦坐实且需要改动代码，就搬进正式的记录。

## 大致的每日安排

下面的天数是软的节奏，不是硬性顺序。各流的实际进度以各自流文件的作业队列为准。

Day8，实验流把误分类重新归因到分类子网，写作流做研究现状的第一批调研，审计流检查差分预言。

Day9，实验流基于上一步的定位修复误分类，写作流做研究现状的第二批调研，审计流检查结构归因。

Day10，实验流搭起定位偏移的定向微调并跑第一轮，可视化流写汇总脚本，审计流检查覆盖账本。

Day11，实验流迭代定位微调并刻画代价、在后台开方差跑，可视化流产出四类指标的统一表和图，审计流检查标定阈值。

Day12，实验流把虚检、漏检的修复推广到其它模型，写作流把研究现状成文并补章节大纲，审计流检查主循环与适配层。

Day13，收尾。把四类修复结果回填到大纲和 E8 文档，定稿表和图，整理审计的偏差清单。
