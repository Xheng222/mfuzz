# 路线图

本文件记录 mfuzz 当前阶段的多日计划，是调度者开始工作时核对方向的依据。它位于计划体系的最上层，给出总体目标和推进顺序。每条工作流的具体待办，写在 `docs/state/streams/` 下对应文件的作业队列里。某一天实际推进哪些任务，由调度者写入自己调度文件的"今日计划"。三类文件各自负责一层信息，不重复记录。

## 当前阶段：Day8 到 Day13

这一阶段的总目标，是把归因分析从虚检、漏检扩展到全部四类失效，把缺陷定位与修复组织成完整叙述，同时推进论文写作、结构化可视化和代码审计。方法不再限定为免训练方法。只要能产生有效结果，训练手段也可以采用。因此，定位偏移的定向微调进入本阶段工作范围，不再只作为展望。

工作按四条工作流并行推进。实验工作流补齐误分类与定位偏移的归因和修复。写作工作流先完成研究现状章节，再补其余章节的大纲。可视化工作流把分散的实验产物汇总成论文需要使用的表格和图。审计工作流逐个模块对照实现方案，确认框架行为与定义一致。四条工作流中，实验工作流受 GPU 串行限制；其余三条不占用 GPU，可以并行推进。每天的安排尽量让各工作流的工作量与时间相当。

## 实验工作流的主要任务

实验工作流先处理误分类。此前把归因目标放在回归头上，责任通道与随机通道难以区分，问题可能来自归因层选择错误。第一步把归因目标换到分类子网，观察责任通道是否明显超过随机对照。这一步同时回答误分类能否定位到单层。定位成立后，再尝试修复。修复先使用抑制；如果抑制无效，再改用定向微调。

定位偏移的因果性此前已经通过剂量响应验证，但抑制和单步权重调整都没有产生有效修复。本阶段改用定向微调处理定位偏移：只解冻责任层，执行少量带 IoU 的微调步骤，并在不相交的评测集上观察定位误差是否下降，以及修复代价有多大。

四类失效都得出结论之后，把它们汇总成一张统一表格。每一类失效都写清责任层级特征、因果验证结论、可用修复办法和修复代价。最后补两件事：多次划分数据集并计算方差，给出可以报告的区间；把虚检和漏检的修复迁移到其他模型上，验证结果是否普遍成立。

## 写作、可视化、审计

写作工作流先完成研究现状的文献调研，分两批进行。第一批覆盖覆盖率引导的测试、对神经元覆盖率有效性的批评，以及差分测试与蜕变测试。第二批覆盖结构归因与可解释性，以及不依赖训练的修复和模型编辑。重点是讲清楚本项目与 DeepFault 这类"先定位可疑神经元、再修复"的工作之间的差异。调研完成后，将内容写成正文，再补其余章节的大纲。

可视化工作流先编写汇总脚本，统一读取各次实验的 result.json，产出对照表与曲线。等实验工作流产出误分类与定位偏移结果后，再制作四类指标的统一表格和图。所有图都不使用热力图。

审计工作流逐个模块对照实现方案检查：差分预言的判定、结构归因的公式、覆盖账本的累计、标定阈值的使用、主循环与适配层的分层。发现偏差时，先记录为假设；核实之后再升级为结论。一旦结论确认成立且需要修改代码，就转入正式记录。

## 大致的每日安排

下面的天数只表示大致节奏，不是硬性顺序。各工作流的实际进度以对应工作流文件的作业队列为准。

Day8，实验工作流把误分类重新归因到分类子网，写作工作流完成研究现状的第一批调研，审计工作流检查差分预言。

Day9，实验工作流基于上一步定位结果修复误分类，写作工作流完成研究现状的第二批调研，审计工作流检查结构归因。

Day10，实验工作流搭建定位偏移的定向微调并完成第一轮运行，可视化工作流编写汇总脚本，审计工作流检查覆盖账本。

Day11，实验工作流迭代定位微调并刻画代价，同时后台运行方差实验；可视化工作流产出四类指标的统一表格和图；审计工作流检查标定阈值。

Day12，实验工作流把虚检、漏检的修复迁移到其他模型，写作工作流完成研究现状正文并补齐章节大纲，审计工作流检查主循环与适配层。

Day13，完成阶段整理。把四类修复结果回填到大纲和 E8 文档，定稿表格和图，整理审计偏差清单。
