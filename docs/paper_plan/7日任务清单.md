# 7 日任务清单：检测迁移 + 结构分析 + 论文大纲

本清单覆盖从 2026-06-08 起的七天。目标是产出论文大纲或写作规划，不是跑完整实验。这七天里的实验都按"探路 / 可行性验证"来做，每天产出一块能拼进大纲的内容。每完成一项勾选 checkbox。

## 背景与已定方向

项目从图像分类迁移到目标检测。分类版的 mfuzz 框架（差分行为、关键神经元覆盖、语义约束、联合优化）已完成 Phase 0 到 5，规格见 `docs/实现方案.md`，历史实验报告见 `docs/archive/`。

经与导师讨论，新方向定了三条：迁移到目标检测模型；做结构分析，找出哪些层、哪些尺度、哪些区域、哪条分支容易出缺陷；最终形成一篇论文。

这周要钉死的贡献声明：

> 提出一种内部反馈驱动的检测模型缺陷定位方法，把检测的四类失效（漏检、虚检、定位偏移、类别错误）归因到模型的具体结构位置——backbone 的哪一阶段、FPN 的哪个尺度、head 的分类分支还是回归分支、特征图的哪片空间区域，给出"检测模型的缺陷在结构上集中在哪里"的系统证据。

论文主线是结构分析，多维反馈框架降级为支撑它的方法。

## 已定选择

- 模型：torchvision 检测库当可靠底座，差分需要的异构模型那里现成。YOLO 作为架构多样性补充，但内部可访问性当成单独风险项验证。
- 数据集：先用 COCO 子集把路趟通。遥测数据集留到需要时再定。
- 主线：结构分析当头号贡献。

## 两条贯穿全周的风险

第一，遥测数据集的标签空间。torchvision 与 YOLO 的预训练权重都是 COCO 80 类。如果遥测数据集的类别和 COCO 对不上，预训练模型直接用不了，差分 oracle 就没法靠现成异构模型搭起来，那意味着要自己在遥测数据上训练多个异构检测器。所以这周探路一律在 COCO 子集上做，遥测数据集那条单独评估"要不要自己训模型"，这个判断越早做越好。

第二，YOLO 的内部激活访问。Ultralytics 的模型底层是 `nn.Module`，理论上能挂 forward hook，但层命名和 torchvision 的 `core/hooks.py` 自动发现逻辑不一样，需要适配。Day 2 专门验证 YOLO 能不能取中间层，取不到就先把 YOLO 当纯黑盒 oracle，只参与差分投票，不参与结构分析。
