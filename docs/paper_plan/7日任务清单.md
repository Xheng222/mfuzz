## 背景与已定方向

项目从图像分类迁移到目标检测。分类版的 mfuzz 框架（差分行为、关键神经元覆盖、语义约束、联合优化）已完成 Phase 0 到 5，规格见 `docs/实现方案.md`，历史实验报告见 `docs/archive/`。

这周要钉死的贡献声明：

> 提出一种内部反馈驱动的检测模型缺陷定位方法，把检测的四类失效（漏检、虚检、定位偏移、类别错误）归因到模型的具体结构位置——backbone 的哪一阶段、FPN 的哪个尺度、head 的分类分支还是回归分支、特征图的哪片空间区域，给出"检测模型的缺陷在结构上集中在哪里"的系统证据。

## 框架通用性与两条风险

原先把"遥测数据集的标签空间对不上 COCO"当成头号风险，Day 2 之后这条想清楚了，换个角度它不是风险而是设计要求。现实里模型和数据集本来就同域配对：YOLO、torchvision 这些 COCO 预训练模型就在 COCO 上测，专门训来认遥感目标的模型就在遥感数据集上测，没有人拿 YOLO 去识别遥测数据，也没有人让遥感模型在 COCO 上跑。所以我们不跨域，而是要求整套框架对(模型集合、数据集、标签空间)三元组参数化，COCO 不焊死在任何地方。同一次实验里这三者必须同域。换到别的域，使用者自带那个域上训好的一组异构检测器和对应数据集即可，框架不用改。

核心方法天然就是通用的。consensus 聚簇、四类失效判定、结构归因，操作的都是检测框和中间层激活，跟具体认什么物体、什么成像方式无关。真正需要留接缝的是每个模型家族的适配层：一个统一的检测器接口，负责加载、前向给出框/类别/分数、暴露可挂 hook 的中间层。torchvision 一个适配器，YOLO 一个适配器，以后遥感模型再加一个，oracle 和归因那层完全不动。

这里有个 Day 2 暴露出来的细节：标签空间怎么定义、怎么获取。每个模型家族暴露自己类别表的方式不一样，而且即便都叫 COCO，索引约定也不同。torchvision 从 `weights.meta["categories"]` 取，是一份长度 91 的列表，索引 0 是 `__background__`，person 在索引 1，里面还夹着 11 个占位项（`__background__` 加 N/A）。YOLO 从 `model.names` 取，是一个长度 80 的字典，索引 0 直接是 person，没有占位。同一个 person，两边索引是 1 和 0。所以差分绝不能按索引比，必须按类别名比：先经各自适配器拿到本地索引到类别名的映射，把每个模型的预测翻成类别名，再在类别名空间里聚簇和投票。一次实验的标准标签空间就定义为参与模型类别名的交集（占位项先剔掉），数据集若带真值做 TIDE 式校验，也要按类别名映射进同一空间。Day 2 的 pilot 三个模型全是 torchvision、共享那份完全相同的 91 列表，所以按索引比侥幸没出错；一旦 YOLO 进来，这个按名对齐的适配层就是必须的，不是可选的。

还剩一条真正的前置条件要记着：差分这条线在任何域都需要至少两个共享同一标签空间的异构检测器。COCO 上 torchvision 白送好几个；换到遥感域，现成的、共享同一套标签空间的异构预训练检测器不一定凑得齐（mmrotate 那类模型库里架构和类别定义经常各不相同）。框架支持任意域这个声明在方法层面成立，但差分分支能不能在某个域真跑起来，取决于那个域有没有凑得齐的异构模型。这是使用者要满足的前置条件，论文里说明即可。

另一条 YOLO 内部激活访问的风险，Day 2 已经解除。`yolo11n` 底层是标准 `nn.Module`，88 个 Conv2d 层全部可挂 forward hook，骨干、neck、头都覆盖到了；唯一要适配的是层命名（`model.0.conv` 这种风格和 torchvision 不一样），属于上面说的模型家族适配层的工作。详见 `docs/paper_plan/Day2/检测迁移可行性.md`。
