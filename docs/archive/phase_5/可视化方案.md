# Phase 5 实验结果可视化方案

## 定位

这份文档说明框架怎么把一次或多次运行的结果变成可看的图和表。目标是让人不读 JSON 就能判断一组实验跑得对不对、几个模块各自起了什么作用。可视化分两层：单个实验内部的图，回答"这次跑出了什么"；跨实验的对比图，回答"换了配置之后差在哪"。两层都由 `evaluate` 模块产出，入口统一，不需要手写画图脚本。

可视化围绕五维指标组织。五个维度是缺陷、覆盖、语义、多样性、效率。每个维度至少有一个图或表的位置承接它，不让某个维度只有数字没有图。

## 产物总览

一次 `run_fuzz` 跑完，结果目录里会有下面这些文件。曲线图随模式变化，diff+cov 出覆盖曲线，纯差分没有覆盖、改出置信度曲线。

| 文件 | 内容 | 对应维度 |
| --- | --- | --- |
| `result.json` | 五维标量指标、各类历史序列 | 全部 |
| `metrics.md` | 五维标量指标分组表；标量本身没有可视结构，列成表不画图 | 全部 |
| `defects.pt` | 缺陷的原始图、变异图、关键神经元激活向量、标签 | 多样性、语义 |
| `clusters.json` | 缺陷聚类概况：簇数、轮廓系数、兜底排除的爆值维数（min-max 下为 0）、各簇的类别直方图与主导类别对 | 多样性 |
| `coverage_curves.png` | CNCov 折线 + CCCov 跨类均值折线与 min-max 带（纯差分模式无覆盖、改出 confidence_curve） | 覆盖 |
| `cccov_heatmap.png` | CCCov 逐类热力图，横轴轮次、纵轴共识类别 | 覆盖 |
| `confidence_curve.png` | 纯差分模式下目标置信度随 PGD 步数下降 | 缺陷 |
| `defect_distributions.png` | 缺陷扰动 L∞ 与关键神经元 ĉ 的直方分布，ĉ 直方标出越界计数 | 缺陷、覆盖 |
| `defect_flow.png` | 缺陷源类别 × 目标类别的流向热力图 | 多样性 |
| `defect_gallery.png` | 缺陷的原始/变异对比图，标注源类别到目标类别 | 缺陷、语义 |
| `defect_clusters.png` | 缺陷激活向量的 2D 投影散点，按簇着色 | 多样性 |
| `diagnostics.png` | 覆盖梯度范数、RFT、$\lambda$ 等逐轮序列，有数据才画 | 缺陷、效率 |

`defects.pt` 把缺陷张量单独存盘，是为了离线重画。`result.json` 只留标量和序列，体积小、能进版本库式的核对；缺陷图像和高维激活向量则留在 `defects.pt` 里，想换一种画法或重新聚类时直接加载，不必重跑整个实验。

跨实验对比另有一套产物，由 `compare_experiments.py` 写到指定目录。

| 文件 | 内容 |
| --- | --- |
| `comparison.md` | 各实验关键标量指标的汇总表，含 CNCov 与 CCCov 跨类均值的末轮值、增益 |
| `compare_cncov.png` | 各实验 CNCov 增长曲线叠加 |
| `compare_cccov.png` | 各实验 CCCov 跨类均值增长曲线叠加 |
| `compare_metrics.png` | 覆盖增益、缺陷数、RFT、OI、簇数的分组柱状图 |
| `compare_radar.png` | 五维代表指标的归一化雷达图，各实验叠一层 |

## 数据通路

可视化接在运行之后，不改运行逻辑。`runner` 把一次运行的全部结果装进 `FuzzReport`，里面有缺陷记录、覆盖历史、各类 CCCov 历史和标量指标。`run_fuzz` 拿到这个对象后交给 `evaluate.report.generate_report`，由它走完评估到出图的全流程。

`generate_report` 的顺序是先算后画。它先对缺陷激活向量聚类，再补齐 runner 没算的多样性、语义、单位代价指标并并回 `report.metrics`，然后写 `result.json` 和 `defects.pt`，最后才画图。核心数据先落盘，是为了即便后面某张图出问题，已经算出的数据也不会丢。

离线重画走另一条路。`defects.pt` 加载回来就是缺陷张量列表，`compare` 和 `validate` 则只读 `result.json`。这意味着出图、聚类、对比、校验都能脱离 GPU 单独跑，不必占着模型重来一遍。

## 单实验的图

覆盖曲线是 diff+cov 的主图。横轴是迭代轮次，纵轴是覆盖率。CNCov 一条折线，反映全局关键神经元覆盖的广度随变异怎么涨。CCCov 的逐类全貌交给热力图，但热力图一眼看不出整体高低，所以这张图里再叠一条 CCCov 跨类均值折线、配一条 min-max 阴影带。两条线同在 [0,1] 纵轴上，一眼比出全局覆盖和类关键覆盖谁高谁低、涨势差多少；阴影带是该轮各类覆盖率的最低到最高范围，带子越宽说明类别越不均衡，随轮变窄说明覆盖在往落后的类别上补。

CCCov 逐类的明暗看热力图：横轴轮次、纵轴各共识类别、颜色是覆盖率。从左到右的颜色梯度看整体涨势，行与行的明暗差看类别之间覆盖均不均衡，哪些类别一直偏冷就是覆盖不足、该让调度往那边倾斜。这张图有没有结构取决于覆盖阈值：阈值太低时各类一上来就接近全覆盖、整片一个色，把阈值定在 $t_{cov}=0.85$ 才让左低右高的梯度和类间明暗带显出来。

缺陷对比图回答语义质量的问题。它取前若干个缺陷，上一排是原始种子，下一排是对应的变异样本，标题标出源类别、目标类别和 L∞ 扰动幅度。变异在 L∞ 约束下幅度很小，肉眼看上去原始和变异几乎一样，这正是想要的：缺陷是模型在近乎不变的输入上给出了不同判断，而不是图被改得面目全非。

缺陷聚类散点回答多样性的问题。每个缺陷在关键神经元集合上的激活向量是它的内部路径指纹，维度很高。聚类用余弦距离，与项目对路径相似度 $S_{path}$ 的定义一致（爆值维兜底排除，min-max 下不触发、排 0 维）。散点把向量按 L2 归一化后投到二维，与余弦几何一致，再按聚类结果着色，图例标出每簇的样本数，标题给出簇数和轮廓系数。散点分得开、轮廓系数高，说明缺陷确实落在几条不同的内部路径上；挤成一团、轮廓系数低，说明缺陷虽然数量多，内部路径却接近，多样性有限。轮廓系数写进标题就是提醒读图的人不要只数有几簇，还要看这几簇分得清不清。

诊断面板放逐轮的辅助序列。当前有覆盖梯度范数这一条（每轮覆盖目标梯度的均范）；RFT 历史、$\lambda$ 权重历史这类要等 Phase 4 的动态反馈接进来才有数据。这张图有哪条画哪条、没有就跳过。把它和主图分开，是不想让暂时为空的序列占住主图的位置。

## 跨实验的图

CNCov 叠加图把多组实验的覆盖增长曲线画在一张图上。每组一条线、一个图例。它最直接的用处是看消融：开覆盖目标和不开、纯频率和纯归因，覆盖曲线谁高谁低、起点和涨速差多少，一张图说清。没有覆盖历史的纯差分实验自动不画线，不会留下一条贴着零的空线。

CCCov 也要能横向比，但跨实验再逐类叠几十条线就糊成一片，所以另出一张 CCCov 叠加图，每组取每轮跨类均值画一条线。它和 CNCov 叠加图并排看，能区分覆盖增益到底是全局铺开还是各类一起涨。汇总表里也给了 CCCov 跨类均值的末轮值与增益两列，和 CNCov 那两列对齐，便于直接读数。

指标柱状图把几个关键标量并排比。每个指标一格，格内按实验并列柱子。覆盖增益、缺陷数、RFT、OI、簇数这五个量分别代表覆盖、缺陷、缺陷、均衡度、多样性几个侧面，并排放能快速看出哪个配置在哪个维度上强、哪个维度上弱。汇总表 `comparison.md` 给出更全的标量，柱状图只挑代表性的几个画。

## 五维指标到产物的落点

缺陷维度的 #Faults、RFT 落在汇总表和柱状图，FRE 落在汇总表，缺陷样本落在对比图。覆盖维度的 CNCov 落在覆盖曲线和 CNCov 叠加图；CCCov 的跨类均值落在覆盖曲线的那条均值线、CCCov 叠加图和汇总表两列，逐类明暗落在热力图。语义维度的输入有效率、平均 $S_{input}$ 落在汇总表，缺陷对比图给出直观印证；这一维要到 Phase 3 把逐候选的语义统计接进来才有真实数值，当前是占位。多样性维度的 #Classes、OI 落在汇总表和柱状图，缺陷簇数和轮廓系数落在聚类散点和 `clusters.json`。效率维度的运行时间、单位时间缺陷数落在汇总表。五个维度都有承接的产物，没有遗漏。

## 设计取舍

图上文字一律用英文。中文标签在缺中文字体的机器上会变成方块，英文标签到哪都能渲染，代价只是图里看英文，文档正文仍是中文。

绘图后端固定用 Agg。它不需要显示环境，能在无界面的服务器和后台进程里出图，适合跑批。

CCCov 分两张图呈现，各管一头。逐类全貌用热力图：共识类别有几十个，几十条线叠一起是一团糊，热力图把每个类别每一轮的覆盖率铺成一格、颜色深浅就是覆盖高低，能看出具体哪些类别始终偏冷。整体趋势用一条线：在覆盖曲线里叠一条 CCCov 跨类均值折线、加一条 min-max 阴影带，让人不细看热力图也能一眼比出 CCCov 和 CNCov 的高低与涨势。均值线和带子就是早期那版最小-中位-最大区间带的思路，单独看信息少；现在让它和热力图配合——线管"整体在哪、类间差多大"，热力图管"具体哪类冷"，两边互补，不再互相替代。

聚类簇数由轮廓系数自动选，不写死。在候选簇数里逐个试，取轮廓系数最高的那个。缺陷太少时不硬分，按一簇处理；激活向量方差塌缩时也按一簇处理。这样簇数是数据自己定的，不是人为指定的。距离用余弦不用欧氏：余弦与 $S_{path}$ 同一表示，且对个别维的尺度异常鲁棒。聚类前保留一条排除爆值维（任一缺陷上 $|\hat c|>1000$）的兜底，那是针对早期峰值归一化产物的；换成区间 min-max 归一化后 $\hat c$ 有界、无维触发，当前排 0 维。被排除的维数记进 `clusters.json`，激活越界本身由 `result.json` 的越界统计报出。

缺陷张量单独存 `defects.pt`，不塞进 `result.json`。激活向量维度上万、图像是稠密张量，塞进 JSON 会让文件膨胀且没法直接读。分开存之后，`result.json` 保持精简可核对，重画和重新聚类则有 `defects.pt` 兜底。

## 复现

可视化随运行自动产出，单跑一个实验就有那一套图。

```bash
uv run python scripts/run_fuzz.py --config configs/diff_cov.toml
```

跨实验对比单独跑，传入若干结果目录，指定输出目录。

```bash
uv run python scripts/compare_experiments.py \
    output/diff output/diff_cov output/diff_cov_lam0 output/diff_cov_a0 output/diff_cov_a1 \
    --out output/compare
```

结果自动校验也读同一批 `result.json`，逐条断言并打印检查表，任一关键项不通过就以非零码退出。

```bash
uv run python scripts/validate_results.py output/diff_cov output/diff
```
